# ALPHA 1.0 - текущая версия
Данный генератор чертежей генерирует дерево рецепта, считает необходимое количество рабочих станций и расставляет их соединяя конвейерами. Работает из консоли, результат в виде хэша который можно вставить в игре через функцию "Импорт строки"
## Запуск и использование
Работает на java 17 (если нет - скачайте) - запускать из консоли по аналогии с примером. Есть проблемы с жидкостями. Для работы необходимо иметь файл data-raw-dump.json в той-же директории что и .jar файл - базовый
я приложу в релиз, но если вы хотите использовать его при space age или модах - 
запускайте в консоли factorio.exe --dump-data в директории с игрой + bin/x64 (например C:\Program Files (x86)\Steam\steamapps\common\Factorio\bin\x64) в папке script-output появится data-raw-dump.json - нужный файл с игровыми данными.
Если у вас что-то не работает - это нормально, недоработок много - исправлю самые критические в течении пары дней после первого релиза.
Для получения строчных кодов предметов/категорий рецептов и пр. Используйте комбинацию клавиш ctrl+shift+F в factorio с наведённым на интересующий объект курсором.

### Общий принцип работы и идея
Располагать рабочие станции в виде дерева, где каждая ветка нижнего уровня следует за веткой более высоких примерно вот так:
<img width="834" height="211" alt="image psd" src="https://github.com/user-attachments/assets/72771788-97f0-4475-843b-b82600eeb220" />:
это позволит им не пересекаться друг с другом, и не нужно решать конфликты (в базовой реализации), а так-же их легко соединять конвейерами.
### Архитектура
Всего есть 4 ключевых класса:
* Main - точка входа и консольный интерфейс
* PrimaryRecipeNode - 1 конкретный ингредиент - содержит ссылку на родительский и дочерние элементы для создания связи
* TreeBuilder - Строит дерево рецепта из PrimaryRecipeNode - всё дерево можно восстановить из первого узла (в коде называемых main/primaryNode)
* SchemeBuilder - Из готового дерева строит физическую схему, пригодную для вставку в игре. Считает необходимое количество рабочих станций под каждый ингредиент и добавляет их на схему,
а так-же расставляет конвейеры. 

Рабочие станции третьего и четвёртого ингредиента смещаются вниз на клетку, если в крафте родительской больше 2 несырьевых ингредиента. Конвейеры соединяются по принципу точек разрыва, 
хранимых в отдельном списке - от линии сборщиков снизу, вправо начинает тянутся линия конвейеров, пока не окажется в точке разрыва (breakPoints в коде). Сами же breakPoints ставятся к верхнему 
правому конвейеру от сборщиков, либо к концу коннектора (смотрите функцию transportBeltsConnecting())
### Текущие проблемы и их потенциальное решение
* ОЧЕНЬ не компактно - решается последовательным перемещением всех узлов вправо со смещением вверх - реализуется легко, но для этого нужно создавать отдельный тип узлов, хранящих все физические объекты,
например PhysicalRecipeNode, для смещения блоками. Так-же после этого можно стянуть влево вниз элементы в обратном порядке - ещё компактнее, но уже сложнее в реализацуии.
* Не поддерживаются жидкости - вы можете подключить рабочие станции с жидкостями, но жидкости обрабатываются как отдельные предметы, так что придётся править в ручную.
Сложно исправить - почти нет наработок
* Не учитывается пропускная способность конвейеров
* Нет отдельного вывода сырья
